# Packages apt installs, one per line. `#` starts a comment.
#
# This list is deliberately short, and the boundary is the reason. apt installs
# what the SYSTEM needs -- compilers, libraries, the shell itself, things other
# packages link against. Everything YOU use comes from mise, which pins with a
# checksum where apt gives you whatever is in the archive that day.
#
# Adding a tool here that mise could install is how the boundary starts leaking.
# The test: would this still need to exist if you never opened a terminal? If
# yes, apt. If no, mise.

# Build toolchain. mise compiles some tools from source and every one of them
# fails without this, with an error that names a missing header rather than a
# missing package.
build-essential
pkg-config
libssl-dev

# The shell. It is the login shell, so it must come from the system: a shell
# installed under a version manager cannot be listed in /etc/shells.
zsh

# Fetching and unpacking, which mise itself needs before it can install anything.
curl
ca-certificates
unzip

# git is here rather than from mise for the same reason as zsh: it is what the
# system's own tooling shells out to.
git

# check.sh parses windows/configuration.winget to verify the host layer stays
# thin and that the Ubuntu resource has not silently changed version. That
# parse needs an interpreter to run and a YAML reader once it is running --
# Python's standard library has no YAML module, so both entries below are
# check.sh's dependency. Do not remove python3 as apparently unused just
# because nothing else here names it directly; it is the interpreter check.sh
# itself runs on.
#
# From apt rather than uv or pip: python3-yaml is a library, not a
# command-line application, so uv-tools.txt is the wrong manifest for it --
# and a check that gates every commit should not depend on a package manager
# that is itself installed by the thing being checked.
python3
python3-yaml

# Task 3's check validates windows/terminal/settings.json against the vendored
# Windows Terminal schema. Same category as python3-yaml above: a library the
# checks need, from apt rather than uv, because uv-tools.txt is for command-line
# applications and because the gate on every commit should not depend on a
# package manager the gate is also checking.
python3-jsonschema

# Docker Engine. This is the one group here that does NOT come from Ubuntu's
# archive: it comes from Docker's own repository, which wsl/install.sh registers
# from wsl/apt/docker.sources before it reads this file. Adding a name here
# without that step produces an installer that works on this machine and fails
# on a clean one, which is the failure this repo exists to prevent.
#
# It passes apt-packages.txt's own test -- would this still need to exist if you
# never opened a terminal? dockerd is a system daemon under systemd, so yes.
# mise cannot install it and should not: mise pins per-project tooling in $HOME,
# not services with a unit file, cgroups and a socket in /var/run.
#
# Docker Desktop is deliberately absent from windows/configuration.winget, and
# docs/decisions.md records why. The short version: GitHub Actions runners carry
# this same daemon, so a native Engine is the only arrangement where dev and CI
# run the same software.
docker-ce
docker-ce-cli
containerd.io
docker-buildx-plugin
docker-compose-plugin
